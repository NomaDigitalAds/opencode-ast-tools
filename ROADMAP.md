# Roadmap

This roadmap starts from the current MVP implementation and prioritizes executable evidence before new features.

## Current State

Already implemented:

- ESM plugin with `ast_grep_search`, `ast_grep_replace`, and `ast_grep_apply`.
- Direct, version-pinned `@ast-grep/cli` execution without a shell.
- Path containment, UTF-8 validation, file-size limits, and bounded output.
- Immutable previews, hashes, TTL, ownership, overlap detection, and single-use apply.
- Same-directory staging, staleness revalidation, and best-effort rollback.
- Unit tests, integration fixtures for all 25 languages on every Tier 1 platform, and npm package builds.
- CI, dependency review, SBOM, provenance, and npm release workflows.
- Tarball installation, tool execution, permission handling, timeout, and cancellation in a real OpenCode instance.
- Deterministic discovery capped at 10,000 language-eligible files with platform-safe command chunking.
- Fault-injected staging, cleanup, commit, rollback, and path-swap coverage.

## Phase 1: CI Baseline

Status: complete.

Goal: turn the existing tests into reproducible evidence outside the development machine.

- Publish the Git repository on GitHub.
- Run `.github/workflows/ci.yml` on Windows x64, Linux x64 GNU, macOS arm64, and macOS x64.
- Correct any language fixture that is incompatible with CLI version `0.44.1`.
- Confirm that `npm ci`, typecheck, tests, build, and `npm pack --dry-run` pass on all four platforms.
- Protect the default branch by requiring a green CI run.

Exit criterion: every Tier 1 platform is green on the same commit.

## Phase 2: Real OpenCode Smoke Test

Status: complete.

Goal: prove the package inside the host that will actually consume it.

- Create a temporary project that installs the tarball generated by `npm pack`.
- Load the plugin in a real OpenCode/Bun installation.
- Invoke search, preview, and apply against a controlled fixture.
- Verify `read allow`, `read deny`, `edit ask`, and `edit deny`.
- Verify child-process cancellation and timeout behavior, including Windows.
- Add this smoke test to the CI matrix.

Exit criterion: all three tools work inside OpenCode, and an `edit: deny` policy prevents every write.

## Phase 3: Discovery And Limits

Status: complete.

Goal: close the main known gap in the specification.

- Measure how many files the CLI can examine before returning results.
- Determine whether ast-grep can reliably interrupt discovery at 10,000 files.
- If it cannot, implement a bounded manifest before engine execution without breaking `.gitignore`, hidden files, or literal paths.
- Avoid command lines above the Windows limit by using deterministic chunks when necessary.
- Add fixtures with more than 10,000 files, ignored files, and paths containing brackets.

Exit criterion: discovery stops deterministically at the limit and reports truncation without reading outside the authorized scope.

## Phase 4: Write Failure Testing

Status: complete.

Goal: prove the staging guarantees and precisely document partial failures.

- Inject failures into temporary-file creation, writing, flush, chmod, and rename.
- Verify that pre-commit failures modify zero targets and leave no temporary files.
- Simulate file changes between preview, staging, and commit.
- Simulate failure after the first rename in a multi-file plan.
- Verify best-effort rollback and `COMMIT_PARTIAL` reporting.
- Test symlink and junction swaps where supported by the platform.

Exit criterion: every apply guarantee has a corresponding failure-path test.

## Phase 5: Public Alpha

Status: in progress.

Goal: publish a usable version without promising premature stability.

- Review the README, examples, error messages, and third-party notices.
- Generate an SBOM and inspect the final tarball contents.
- Configure npm credentials or trusted publishing.
- Publish `0.1.0-alpha.1` with provenance.
- Install the published version, rather than the local workspace, in the OpenCode smoke test.
- Document known limitations and the bug-reporting process.

Exit criterion: a version-pinned public package installs successfully and passes the smoke test using the published artifact.

## Phase 6: Stabilize 0.1.0

Goal: promote the alpha only after real-world use.

- Collect feedback from real codemods and adjust limits only when evidence supports it.
- Measure duration, memory, and output size without logging source code.
- Fix incompatibilities found in the language matrix.
- Freeze the contracts of all three tools and their error categories.
- Publish `0.1.0` after a period without critical regressions.

Exit criterion: documented contracts, a green Tier 1 matrix, and no known critical containment, staleness, or permission failures.

## Outside The Critical Path

Consider these only after the MVP is stable:

- Structured rules with `inside`, `has`, `precedes`, and `follows`.
- Optional NAPI backend for JavaScript and TypeScript.
- Crash-recoverable journal for multi-file commits.
- Incremental indexing.
- Pattern explanation and debugging tool.

These items must not delay validation and release of the basic search -> preview -> apply workflow.
